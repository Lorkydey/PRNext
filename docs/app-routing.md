# Parallel and intercepting App routes

PRNext discovers named `@slot` directories and passes each slot as a prop to its owning layout. Slot names and route groups do not add URL segments. `children` remains the implicit slot. Pages in distinct slots may share a URL; duplicate pages in the same slot are build errors.

On a document request, each slot independently selects its matching page. A slot with no matching page renders `default.js` (or another configured source extension). Missing defaults produce a 404, including the implicit children slot. Soft navigation preserves unmatched slots and their existing React state, without executing their Server Components again. Matching pages update while shared layouts keep their state.

`(.)`, `(..)`, repeated `(..)(..)`, and `(...)` resolve against URL segments, ignoring slots and route groups. Interception applies to soft navigation from an active source route. Direct requests and reloads render the canonical destination. An intercepted layout can itself contain another intercepted slot: opening, refreshing, closing, and returning to the inner view preserve the outer view and its background. Ancestor interceptions must already be active before an inner interception can activate. A root-relative link inside an intercepted view can continue through that view while preserving its source layout.

Separate root layouts in route groups are identified by their source layout. Navigation within one root preserves mounted state; crossing to another root performs a document navigation so its `<html>` and `<body>` are applied. Ordinary routes and routes containing slots use this rule.

`useSelectedLayoutSegments(key)` reports the selected branch of the nearest layout. Route groups remain in the result and catch-all values are joined with `/`. `useSelectedLayoutSegment()` returns the first child segment; for a named slot it returns the last selected segment, matching Next's implementation. Defaults return no selected segment. `useParams()` includes the parameters of active source layouts and the destination.

Slot-level `loading`, `error`, and `not-found` boundaries surround that slot. Server exceptions are redacted in production. A slot's `notFound()` can return 404 while preserving healthy siblings. `generateStaticParams` runs along ordinary branches, memoizes shared parent generators during one route inspection, and combines distinct concrete paths from parallel branches before prerendering HTML/Flight pairs. Interception-only branches do not create canonical static paths.

Each slot's page and layout receive their own scoped parameter names. Equivalent URL patterns may use different names in separate slots, including catch-all names; static paths generated by those slots are normalized to the public children route's parameter names before HTML and Flight generation.

Metadata and viewport resolve across active layouts and pages, including named slots and retained unmatched branches. Named slots precede ordinary children, in deterministic name order, matching Next's loader-tree precedence; `generateMetadata` receives metadata accumulated from preceding items. The final leaf's title template does not apply to its own page. Retained metadata can be regenerated without executing the retained page's Server Components. File metadata is loaded with its originating entry and parameters.

Soft navigation carries a bounded, validated `x-prnext-router-state` header. Rust bypasses the canonical Full Route Cache for this Flight request and returns a private response varying on router state. Public canonical HTML and Flight entries remain unchanged. Router state is routing input, never authentication or authorization data.

`router.refresh()` and Server Action responses reconstruct all active branches, including unmatched background slots, from their saved URLs and parameters. Additional server entries are imported on demand through the build manifest. Ordinary navigation retains the previous page content while resolving its metadata. Source access URLs run through the native routing pipeline again as GET, under the current credentials, including cookies changed by an action. Configured headers and redirects, middleware, chained `beforeFiles`, filesystem precedence, `afterFiles`, dynamic routes and `fallback` retain their normal order. A forged or stale state cannot bypass that check. Restored sources with encoded path literals receive the same access check as their decoded App route.

Middleware request-header replacements and response cookies receive a separate context for the source subtree, including async descendants and metadata generators. A nested React Flight render maintains that context without applying the source's headers, new cookies, private cache, or Draft Mode provider to sibling branches. All nested streams share a 16 MiB limit and cancel together if it is exceeded. Rust supplies the original incoming headers before the destination's middleware runs. Source middleware cookies are included in the response for subsequent browser requests. Internal aliases retain both the visible access URL and the effective route URL, including query parameters; native routing must resolve that alias to the saved route again before restoration. The physical route is not separately probed outside its rewrite.

The routing worker uses an authenticated loopback bridge to the same Rust routing implementation that handles public requests. Its internal probe marker cannot be supplied as an HTTP header. Probes stop before page execution, caches and static rendering; they never fetch an external rewrite destination. The bridge admits eight concurrent probes, limits each to five seconds and caps incoming headers at 64 KiB and replies at 192 KiB. Builds and direct programmatic rendering without the native server retain the middleware-only verifier and refuse configuration aliases they cannot verify.

Recent history retains at most 16 Flight models and their active slot snapshots. Returning to one after its layout has unmounted restores server content without re-fetching it; client state inside an unmounted component remounts normally. Older history entries reconstruct their saved branches on the server. An invalid or inaccessible saved tree falls back to a canonical document request.

## Current limits

- A saved source whose routing now redirects, rewrites externally, resolves to a different effective route or selects a public file falls back to a canonical document request. Access revalidation is bounded to 32 distinct saved URLs and a ten-second total deadline.
- Navigation carrying retained advanced routing state uses live SSR when Cache Components is enabled. Its credential-dependent source tree is not shared through a canonical PPR artifact. Document requests without retained state remain eligible for PPR.
- This is PRNext's Flight/router-state protocol. It is not an implementation of Next's private wire protocol or segment-prefetch protocol.

Validation lives in `tests/browser/app-routing.spec.mjs`, `tests/browser/app-routing-rewrites.spec.mjs`, `tests/app-routing.test.mjs`, `tests/app-routing-rewrites.test.mjs`, and `packages/prnext/build/app-routing.test.mjs`. The HTTP suite verifies that an intercepted response cannot replace a canonical cache entry and rejects forged, redirected or changed source aliases. Browser tests cover all rewrite phases, state preservation, credential isolation, refresh, actions and logout under configuration-only redirects. A native bridge test checks authentication, input bounds and resolution with no render executable available.

## Source suffix configuration

`pageExtensions` applies to Pages routes, `_app`, `_document`, Pages errors, App conventions, API handlers, and middleware/proxy. For example, `pageExtensions: ['page.tsx', 'route.ts']` recognizes `pages/index.page.tsx`, `app/layout.page.tsx`, `app/page.page.tsx`, and `proxy.route.ts`, while excluding ordinary `.tsx` files from discovery. Imported helpers are still compiled normally.

PRNext retains its previous defaults: `tsx`, `ts`, `jsx`, `js`, `mjs`, `cjs`. Next's documented defaults contain the first four. Compound suffixes use the longest configured match. Markdown/MDX and custom compiler loaders remain unsupported; discovering one produces an explicit diagnostic. [Next pageExtensions reference](https://nextjs.org/docs/app/api-reference/config/next-config-js/pageExtensions).
