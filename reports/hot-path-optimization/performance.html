04 / Du Rust, là où il fait la différence

La vitesse commence
par le travail évité.

Rustyx allège les chemins fréquents tout en conservant Node et React pour exécuter le code JavaScript et les modules npm.

01 — SERVIR

Les hits restent
près du métal.

ISR et images en cache passent par le serveur natif. Sur ces charges seules, Rustyx peut répondre sans même démarrer le worker JavaScript.

02 — PARTAGER

Les mêmes octets.
Moins de copies.

Les réponses partagent les images déjà encodées. Le cache chaud dispose d’un budget comptable de 1 Mio ; les grandes images restent sur disque.

03 — ALLÉGER

Chaque réponse
fait moins de détours.

Moins de lectures disque, d’allocations et d’échanges entre Rust et JavaScript. Le principal progrès face à l’ancien Rustyx concerne le CPU.

Le Flight est-il nettement meilleur que Next.js ?

Son avantage CPU est modeste : environ 3 % sur les essais courts et 5 % sur l’observation de 30 secondes. Les plages des essais courts se recouvrent. Le débit progresse davantage, mais cela ne garantit pas une avance CPU sur toutes les applications.

Un site complet peut-il tenir dans 10 Mio ?

Les quelque 10 Mio mesurés concernent des hits ISR ou images isolés, après redémarrage du serveur, sans lancer Node. Un site qui exécute du JavaScript ou effectue un rendu React utilise davantage de mémoire. Les parcours mixtes incluent les workers démarrés.

La dernière optimisation réduit-elle énormément la RAM ?

Le progrès principal est le CPU. La RAM des API reste proche de l’ancien Rustyx ; certains parcours peuvent en utiliser un peu plus. L’avantage face à Next.js ne doit pas être confondu avec le gain apporté par cette seule série de changements. Activez « Rustyx avant optimisation » dans le comparateur pour voir la différence.

Que mesure exactement le CPU par réponse ?

C’est le temps processeur de l’ensemble des processus serveur, divisé par le nombre de réponses valides. Un serveur plus rapide peut consommer davantage de CPU total à saturation tout en coûtant moins par réponse. Ces deux mesures sont disponibles dans le comparateur.

Comment la mémoire est-elle comptée ?

Le RSS additionne les processus serveur, y compris Node et les workers RSC, sans recompter les threads d’un même processus. Certaines pages partagées entre processus peuvent être comptées plusieurs fois. Les pics sont échantillonnés et les budgets des caches ne plafonnent pas la RAM totale de l’application.

Est-ce compatible avec tous les projets Next.js ?

Les projets de cette campagne passent leurs comparaisons fonctionnelles. Cela ne certifie pas une compatibilité exhaustive : les conventions et dépendances de votre propre projet doivent être vérifiées. Consultez la matrice de compatibilité avant de migrer.
